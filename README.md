# 还差多少

> 把「你想做到的事」和「你实际花掉的时间」摆在一起对照。

一个单页网页工具。让用户随时看清三件事：

1. **我走到哪了** —— 还差多少天
2. **我的力气花在哪** —— 哪一步吃掉的时间最多
3. **有没有走偏** —— 有没有一步投入明显过多，或长期为零

它不帮你做得更快。它是一面诚实的镜子。

---

## 为什么做这个

市面上有「记事的」（待办工具），也有「记时间的」（时间统计）。
**把两者和目标放在同一张表上的，没有。**

用户行为其实已经交付完成 —— 他清楚知道自己做了什么，
但从未把它和目标结构对照过。绝大多数误判都源于「从未对照」，
而不是「不知道自己在做什么」。

典型场景：

> 接了三个月 PPT 单子，做得很辛苦，
> 但离真正想做的 AI 编程出海越来越远。
> 把时间和目标拆开一对照才发现，那一步只值 1 天，他花了 12 天。

## 核心设计

| 原则 | 说明 |
|---|---|
| 主语是「你」 | 界面里不出现「系统」「平台」，只出现「你」 |
| 主数字用天数 | 百分比是评价，天数是可以完成的东西 |
| 判断用事实句 | ✅「这一步值 1 天，你花了 12 天」❌「效率低下」 |
| 不做评分徽章 | 一旦引入评价，用户会开始刷分，产品变成表演 |
| 距离旁边必须有「下一步」 | 距离单独出现会变成压力，配合动作才是帮助 |

完整规范见 PRD 第 4 章（产品原则）与第 10 章（文案规范）。

## 技术方案（MVP）

    单页应用（单个 HTML 文件）
    状态：localStorage
    部署：Vercel / Cloudflare Pages

**不做登录、不做数据库、不做接口。**
这三件事加起来会吃掉两周，且不产生任何验证价值。

数据存在用户浏览器里，第三屏常驻导出链接。
云端同步（Supabase）留到第 3 周之后。

**这项目前 3 周的瓶颈是「想清楚要说什么」，不是「写得出来」。**

## 路线

| 里程碑 | 内容 | 判定 |

| M1 可用原型 | 三屏跑通，纯本地 | 自用 3 天无障碍 |

| M4 定型 | 留存达标 + 导出可用 | D7 留存 ≥ 40% |
| M5 决策 | 继续 / 砍掉 / 换切口 | — |

**停止条件**：若 D14 时 5 人中留存 ≤ 1 人，停止加功能，回到访谈重新定切口。
