## 1. 产品定义

**一句话**：把"你想做到的事"和"你实际花掉的时间"摆在一起对照，让误差无处可藏。

**它不做什么**：

| 做 | 不做 |
|---|---|
| 把力气和目标摆在一起对照 | 帮你把活干完 |
| 诚实显示错配 | 安慰你"你已经很努力了" |
| 让距离随时可见 | 优化你的效率参数 |

它是一面诚实的镜子，不是效率工具。效率工具要你相信它能让你更快；镜子只要让你看清。

**核心判断依据**：用户行为已经交付完成——他清楚知道自己做了什么，但从未把它和目标结构对照过。绝大多数误判（伪努力、方向偏移）都源于"从未对照"，而不是"不知道自己在做什么"。

---

## 2. 要解决的问题

### 2.1 现象

- 用户能清楚描述自己做了什么，但说不清这些事与目标的关系
- 投入时间与目标结构长期不一致，且没有人指出
- 待办类工具记录"待办"，但不记录"时间实际去了哪"
- "高认知穷人"式的失败：做了大量正确的局部动作，但打偏了靶子

### 2.2 现有方案为什么不够

| 方案 | 它解决了 | 它没解决 |
|---|---|---|
| 待办 / 任务管理 | 记事情 | 不记时间去向；不与目标对照 |
| 目标管理（OKR） | 拆目标、定指标 | 拆得再准也不记录实际投入 |
| 时间统计 | 记录时间去向 | 纯记录，不对照目标，产生不了判断 |
| 复盘 / 效率工具 | 事后分析 | 频率低（周/月），反馈滞后 |

**结论**：市面上有"记事的"和"记时间的"，没有把两者和目标放在同一张表上的。这是空位。

### 2.3 产品只负责产出三种判断

1. 我走到哪了（距离）
2. 我的力气花在哪（分布）
3. 有没有一个地方投入明显过多，或长期为零（错配）

不多不少。

---

## 3. 目标用户

### 3.1 首要画像：长周期目标的执行者

- 有明确的、超过 3 个月的目标（做出产品、转行、学一门技能、健身）
- 日常在做事，但说不清进度
- 特征：**目标大、周期长、没有即时反馈**
- 典型内心台词："我好像挺努力的，但不确定有没有在靠近。"

### 3.2 明确排除

- 纯事务型日程管理（用日历即可）
- 团队协作 / 项目管理（本产品是个人工具）
- 探索型用户（不想要距离反馈）→ 通过"探索模式"容纳，但不作为首批目标用户

---

## 4. 产品原则（开发时的红线）

1. **主语是用户，不是系统。** 界面不出现"系统检测到""平台分析"，只出现"你"。
2. **主数字用天数，不用百分比。** 百分比是评价，天数是可以完成的东西。
3. **判断用事实句，不用评价词。**
   - ✅「这一步本来 1 天就够，你已经花了 12 天」
   - ❌「你效率低下」「严重偏离目标」
4. **不做进度评分、不做徽章、不做连续打卡天数。** 一旦引入评价，用户会开始刷分，产品变成表演。
5. **距离旁边永远紧跟一个"下一步"。** 距离单独出现会变成压力，配合动作出现才是帮助。
6. **诚实优先于好看。** 数据缺失时显示"没有记录"，不补默认值、不美化。

## 5. MVP 范围

### 5.1 做

| 功能 | 优先级 |
|---|---|
| 创建目标（写结果） | P0 |
| 拆成 3–7 步，每步估天数 | P0 |
| 标记 / 取消完成 | P0 |
| 每天记一笔（关联到步骤） | P0 |
| 每周查看：距离 + 力气分布 + 错配提示 | P0 |
| 数据导出（JSON + 纯文本） | P0 |
| 首次进入的预填示例 | P1 |
| 探索模式开关 | P2 |

### 5.2 明确不做

- AI 拆解目标——用户自己拆更准；且 AI 一旦给出"我帮你拆好了"，就是在做假承诺
- 提醒 / 推送通知
- 多目标并行
- 分享 / 社交 / 排行榜 / 徽章
- 移动端原生 App
- 团队协作
- 账号体系、云端同步（第 3 周后另立需求）

## 6. 信息架构与页面流程

```
首次进入
   │
   ▼
预填示例  ──▶ 一键改成自己的
                  │
    ┌─────────────┴─────────────┐
    ▼                           ▼
① 建目标（一次性，约 3 分钟）   ② 记一笔（每天，约 5 秒）
   ├─ 写结果                       ├─ 今天做了哪一步？
   ├─ 拆 3–7 步                    ├─ 在做基础 / 别的
   ├─ 每步估天数                    └─ 完成即写入
   └─ 结束 → 当场看到距离                 │
                                          ▼
                                   ③ 看一眼（每周，约 2 分钟）
                                   ├─ 你已经走了 X 天
                                   ├─ 还差 Y 天
                                   ├─ 力气花在哪
                                   ├─ 有没有走偏
                                   └─ 下周要不要改
```

**无导航栏。** 三个页面靠状态流转，不靠用户找。

- 首次 → ①
- 每日 → ②
- 每周或用户主动 → ③
- ② ③ 之后都能回到 ① 编辑目标与步骤

## 7. 功能需求

### P1 创建目标

**目标**：让用户 3 分钟内产出一个可用的目标结构。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 你想做到什么 | 文本 | 是 | 必须写结果，带示例引导 |
| 备注 | 文本 | 否 | — |

**验收标准**

- [ ] 首次进入时表单已被示例预填，用户可直接提交体验
- [ ] 提交后进入拆步骤页，不回填
- [ ] 步骤数为 0 的目标允许保存，第三屏提示去拆步骤
- [ ] 目标数量上限 1；已有目标时新建入口隐藏

**引导文案**

> **你想做到什么？**
> *例：自己做出一个海外用户愿意付钱的产品*
>
> 💡 **写结果，不写过程**
> "减肥" → "体重从 78 到 70"
> "做自媒体" → "一个月发出 10 条，其中 5 条被收藏"

---

### P2 拆步骤

**目标**：产出 3–7 个可打钩的步骤 + 权重。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 步骤名称 | 文本 | 是 | 必须可验证 |
| 大概要几天 | 整数 1–90 | 是 | 权重 |

**约束**

- 步骤数 3–7。少于 3 提示"再拆细一点"，多于 7 提示"挑最重要的 7 个"
- 步骤顺序 = 推荐执行顺序，第一步即"接下来做这个"

**验收标准**

- [ ] 步骤可增删、可调序
- [ ] 天数可随时修改，改动后距离实时重算
- [ ] 完成后直接展示第三屏首屏内容（当场看到距离）
- [ ] 每一步提供"做出来是什么样"的提示

**引导文案**

> **这一步做完，什么东西会存在？**
> *例：有一个能打开的网址*
>
> 💡 **要"做出来"，不要"了解"**
> ❌ 了解 AI 编程原理　✅ 自己写一个能跑通的 demo
> ❌ 学英语　✅ 录一段 2 分钟英文介绍发出去
>
> **这一步大概要几天？**　*凭感觉就行，估小一点没关系*

**步骤命名规范**

| 目标 | ❌ 差 | ✅ 好 |
|---|---|---|
| 做出海产品 | 提升编程能力 | 自己写一个后端接口并部署上去 |
| 做出海产品 | 找用户 | 找 10 个人来试 |
| 做出海产品 | 变现 | 收到第一笔钱 |
| 减肥 | 控制饮食 | 每天吃够两拳头主食 |
| 减肥 | 坚持运动 | 每周三次、每次 30 分钟 |

规律：**能打钩的才是步骤，打不了钩的是愿望。**

---

### P3 记一笔

**目标**：5 秒内完成一次记录。这是留存的关键，摩擦必须最小。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 记给哪一步 | 单选（步骤按钮组） | 否 | 选中即视为「推进目标」 |
| 归类 | 单选 | 条件必填 | 仅当未选步骤时出现 |
| 基础用点 | 文本 | 条件必填 | 仅当选「在做基础」时出现 |
| 备注 | 文本 | 否 | 默认折叠 |

**关键设计**：`step_id` 一填，"推进"就自动成立。日常只需点一下"今天做了第 3 步"，不需要再选分类。这是把 2 秒守住的核心。

**验收标准**

- [ ] 从打开到记录完成 ≤ 2 次点击（关联步骤时）
- [ ] 记录后有明确反馈（数字/文案变化），不跳转页面
- [ ] 误触可撤销
- [ ] 不允许空提交

**引导文案**

> **刚才做了什么？**
> ○ 推进目标——就是在做某一步
> ○ 打基础——为了以后某件事，现在得先学
> ○ 别的——跟目标无关
>
> 选"打基础"的话，顺手答一句：**这东西什么时候用得上？**
> *不填的话，它下次就只会被算进"别的"*

---

### P4 看一眼（第三屏 / 主界面）

**目标**：2 分钟内给出距离感与错配提示。**这是产品的全部价值所在**，前两屏只是为它供数。

**区块顺序（自上而下）**

**区块 1｜距离**

> **还差多少**
> 你已经走了 **5 天** · 完成 2 / 6 步
> 还差 **8 天** · 大概一周多

- 「已经走了」只增不减（累计感）
- 「还差」可增可减（后补步骤会导致增加，属正常）
- 下方必须紧跟区块 2

**区块 2｜现在做这个**

> **接下来做这个**
> 找 10 个人来试 · 大概 4 天

规则：取第一个未完成步骤。

**区块 3｜拆出来的步骤**

每步显示：名称、估天数、完成状态、累计投入。
点击可切换完成状态 / 修改天数。

**区块 4｜这 30 天，你的力气花在哪**

按步骤与类别列出，含两种提示：

- 投入过头：「收到第一笔钱」你花了 12 天 · 这一步本身只要 1 天
- 从未碰过：「找 10 个人来试」你花了 0 天 · 这一步要 4 天，是最重的一步

**区块 5｜导出**

常驻「导出我的数据」链接（JSON + 纯文本两档）。

**验收标准**

- [ ] 任何数据变化后 1 秒内刷新
- [ ] 无数据时显示引导而非空白
- [ ] 告警文案为事实句，不含评价词
- [ ] 320px 宽度下不横向滚动、不截断文字

## 8. 数据结构

```sql
goals(
  id          TEXT PK,
  title       TEXT NOT NULL,     -- 短标题
  result      TEXT NOT NULL,     -- 想做到的结果
  mode        TEXT NOT NULL,     -- 'focus' | 'explore'
  created_at  INTEGER NOT NULL
)

steps(
  id          TEXT PK,
  goal_id     TEXT NOT NULL,
  name        TEXT NOT NULL,     -- 必须可打钩
  days        INTEGER NOT NULL,  -- 1..90，权重
  done_at     INTEGER NULL,      -- 完成时间戳，可取消
  added_later INTEGER NOT NULL DEFAULT 0,
  sort_order  INTEGER NOT NULL,
  created_at  INTEGER NOT NULL
)

logs(
  id          TEXT PK,
  step_id     TEXT NULL,         -- 有值 => category 视为 'push'
  category    TEXT NOT NULL,     -- 'push' | 'basic' | 'other'
  basic_use   TEXT NULL,         -- 仅 basic 有效
  minutes     INTEGER NOT NULL, -- 见 9.3
  note        TEXT NULL,
  logged_date TEXT NOT NULL,     -- YYYY-MM-DD，本地时区
  created_at  INTEGER NOT NULL
)
```

**索引**：`steps.goal_id`、`logs.step_id`、`logs.logged_date`

**存储（MVP）**：localStorage，key `haicha.v1`。结构版本化，为后续迁移 Supabase 留口。

## 9. 计算规则

### 9.1 距离

```
total_days = Σ steps.days
done_days  = Σ steps.days WHERE done_at IS NOT NULL
left_days  = total_days - done_days
progress   = done_days / total_days    -- 仅作副文案，主数字是 left_days
```

### 9.2 累计推进（只增不减）

`cumulative_days` 为独立累加字段：取消完成时**不回退**，重新完成时**不重复累加**（按 step_id 去重）。保证"已经走了"这个数永远不倒退。

### 9.3 投入折算

MVP 按"天"为单位估算，不要求精确：

```
spent_days(step) = Σ 该步记录的 minutes / 480
```

**待定项**：单笔记录默认 0.5 天，按钮可切「半天 / 一天」。此参数需在首周用户测试中校准。

### 9.4 错配判定

```
over_invested = spent_days > days AND done_at IS NULL
never_touched = spent_days == 0 AND days >= median(days)
```

规则只有这一条，没有例外条件——所以技术成本几乎为零。

### 9.5 复盘周期

按自然周（周一至周日）。显示最近 4 周分布，当前周高亮。

## 10. 文案规范

### 10.1 术语禁用清单

| 禁用 | 替换为 |
|---|---|
| 里程碑 / Milestone | 一步 / 步骤 |
| 加权 / 权重 | 这步大概要几天 |
| 里程表 | 你已经走了 X 天 |
| 油表 / 进度条 | 还差 X 天 |
| 分账比例 | 你的力气花在哪 |
| 效率 / 效能 | 力气 |
| 复盘 | 看一眼 |
| 投入过度 / 偏离 | 这一步值 X 天，你花了 Y 天 |

### 10.2 全屏文案表

**第三屏**

| 位置 | 文案 |
|---|---|
| 副标题 | 你想做到：{result} |
| 区块1 标签 | 还差多少 |
| 区块1 主 | 你已经走了 {X} 天 · 完成 {n}/{N} 步 |
| 区块1 次 | 还差 {Y} 天 · {人话时长} |
| 区块2 标签 | 接下来做这个 |
| 区块2 内容 | {首个未完成步骤} · 大概 {d} 天 |
| 区块4 标题 | 这 {n} 天，你的力气花在哪 |
| 区块4 过头 | 「{step}」你花了 {s} 天 · 这一步本身只要 {d} 天 |
| 区块4 空缺 | 「{step}」你花了 0 天 · 这一步要 {d} 天，是最重的一步 |

**边界文案**

| 场景 | 文案 |
|---|---|
| 全部完成 | **6 步全走完了。** 你在这个目标上花了 {total} 天。下一个目标是什么？ |
| 后补步骤 | **你新发现了 {n} 步，距离重新算了一次。** 不是倒退。是你现在看得比之前清楚了。 |
| 连续 7 天无记录 | **这 7 天没有记录。** 没关系。要不要看看上次停在哪？ |
| 无任何记录 | 还没有记录。先记一笔，就能看到距离。 |
| 探索模式 | （隐藏距离，只显示）你已经走了 {X} 天 |

**禁忌文案**

- ❌ 你已连续 7 天未完成目标
- ❌ 目标已完成
- ❌ 严重偏离目标 / 效率低下
- ❌ 恭喜你解锁成就

## 13. 验证计划

### 13.1 阶段

| 阶段 | 天数 | 目标 |
|---|---|---|
| 自测 | D1–D6 | 跑通全流程；D4–D6 只改文案 |
| 冷启动 | D7 | 5 人首次使用，记录耗时与卡点 |
| 陪跑 | D8–D14 | 只陪不改，每日问"昨天记了吗" |
| 定型 | D15–D21 | 只修阻碍项，加导出 |

### 13.2 指标

| 指标 | 合格线 | 采集方式 |
|---|---|---|
| 首次用完耗时 | < 2 分钟 | 人工计时 |
| 单次记录耗时 | < 15 秒 | 人工计时 |
| D7 留存人数 | ≥ 2 / 5 | 人工确认 |
| 周复盘打开率 | ≥ 50% | 导出行为反推 |
| **有人复盘后主动改计划** | ≥ 1 人 | 人工访谈 |

最后一条是唯一能证明"产品有用"而非"界面好看"的证据。

### 13.3 停止条件

若 D14 时 5 人中留存 ≤ 1 人：**停止加功能，回到访谈重新定切口**，不进入云端开发。
